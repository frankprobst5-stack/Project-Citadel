Category 01: Surveillance & Security Cameras (RTSP/ONVIF)

To pull live video streams without external corporate cloud servers, hardware must support raw Real-Time Streaming Protocol layout channels.

📷 Reolink Cameras (RLC Series Primes) Commercial-grade, rugged exterior security hardware. When isolated from the internet, they drop high-definition RTSP streams straight onto your local router.
• Target Protocol Route: rtsp://[Device_IP]/h264Preview_01_main
📷 Amcrest Hardware (UltraHD Series) Standard hardware units equipped with native ONVIF and RTSP broadcasting options accessible right out of the box with zero external firmware compilation modifications required.
📷 ESP32-CAM Micro-Node (Open DIY Option) A budget-friendly, open-source micro-controller board featuring a built-in lens module. Flash it with custom offline code to stream low-power, lightweight video blocks anywhere inside your perimeter lines.
🔌 Connecting a camera to Vigil (added 2026-09-16) Vigil has no manual "add device" form — like every other device type here, a camera is registered with one real API call, then its live feed shows up automatically on the dashboard. Point it at your own camera's real RTSP URL (the pattern above for your model), not a placeholder:
curl -X POST http://<citadel-host>:8082/api/register \
  -H "Content-Type: application/json" \
  -d '{"device_id": "front-porch-cam", "ip": "192.168.1.50", "type": "camera", "rtsp_url": "rtsp://192.168.1.50:554/h264Preview_01_main"}'
Vigil bridges the RTSP feed to a browser-viewable stream itself (RTSP can't be shown in a plain web page directly) — no extra software needed on your end beyond this one call. Re-run the same command with a new rtsp_url if the camera's address ever changes.
